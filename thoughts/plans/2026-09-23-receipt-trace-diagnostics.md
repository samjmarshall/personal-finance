# Receipt trace diagnostics — fold "More details" (variant C) into the real dialog

## Context
The receipt detail dialog has no way to trace a receipt's upload/ingest through
PostHog. A throwaway prototype (variant C — trace header + tabbed drawer) proved
the shape but mocks the trace id and hardcodes the PostHog link. This plan folds
C into production: persist the real ingest **trace id** on the receipt row,
surface it plus a server-built PostHog trace-viewer deep-link on the detail
query, and replace the prototype with a real diagnostics section.

## Current State
- **No trace column.** `receipts` table has no trace field (`src/server/receipts/receipts.schema.ts:23-64`). The `Receipt` interface has none either (`src/domain/receipts/receipt.interface.ts:3-23`).
- **The id already flows, unpersisted.** The browser mints one W3C `traceparent` per request (`src/lib/traceparent.ts:13-15`, adr018) sent on the tRPC batch (`src/trpc/react.tsx:19`); Next parents the server span onto it, so one trace id runs from the browser through the server span tree. adr016's `_trace` pocket (`src/server/inngest/events.ts:37-42`, restored at `src/server/observability/inngest-middleware.ts:40-41`) makes the `process-receipt` worker **continue that same trace** — so the id known at `receipt.create` is the id the extraction runs under. It is read anywhere via `trace.getActiveSpan()?.spanContext().traceId` (precedent: `src/app/api/trpc/[trpc]/route.ts:13`, `src/server/observability/posthog.ts:31`). There is **no** `readTraceId()` helper today.
- **Prototype is live.** `src/app/_components/receipts/more-details.prototype.tsx` (mock id `mockTraceId` :56-64, hardcoded PostHog host/project :66-77) + `src/app/_components/prototype-switcher.tsx`, wired into `src/app/_components/receipts/receipt-detail.tsx:33-38,519-521`.
- **Read path spreads all columns.** `receipt.get` returns `...getTableColumns(receipts)` + `transactionDescription` (`src/server/api/routers/receipts.ts:120-153`), so a new column reaches the wire automatically; only the hand-authored TS type needs the field.
- **Env is server-only.** `POSTHOG_HOST` (ingest endpoint, default `https://us.i.posthog.com`) + `POSTHOG_PROJECT_ID` sit in the `server` block; `client: {}` is empty (`src/env.ts:114-116,131-133`). No `NEXT_PUBLIC_` vars exist.
- **Receipt creation sites (capture points):** upload `receipt.create` insert (`src/server/api/routers/receipts.ts:69-76`), `retry` update (`:163`), inbound email (`src/server/email/email.service.ts:140` → `src/server/email/email.repository.ts:57-82`).

## Desired End State
- `receipts` has a nullable `trace_id` text column, populated at creation (upload, retry, email) with the active span's 32-hex lowercase trace id; null when OTel is unregistered (e.g. `POSTHOG_KEY` unset locally).
- `receipt.get` returns `traceId` (the raw id, copyable) and `traceUrl` (a server-built PostHog trace-viewer link, or null).
- The dialog shows a real **Developer details** section: X-Trace-ID + Copy + "Open trace" link, and tabs **Timeline / Raw / Metadata** — all from real data. The prototype and switcher are deleted.
- A new server env `POSTHOG_UI_HOST` (default `https://us.posthog.com`) is the *only* source of the viewer host.

## Out of Scope
- User-aware gating (PostHog cohort / `isDeveloper` toggle) — deferred until a failure corpus exists (per the original brief).
- An in-app per-span waterfall — real span timings live in PostHog; "Open trace" is the path to them. (The prototype's mocked "Trace" tab is dropped, not productionised.)
- `NEXT_PUBLIC_` client env / `posthog-js` client instrumentation (adr015 future work).
- Backfilling `trace_id` on existing rows — the column is nullable; historic rows stay null.

## Approach
Capture the producer trace id at each receipt-creation site and persist it in a
new nullable column (Phase 1). Add a `POSTHOG_UI_HOST` env and a pure, tested URL
builder, and expose `traceId` + `traceUrl` on the detail query (Phase 2). Replace
the prototype with a production diagnostics component reading real data, extract
the status→stages logic into a tested pure helper, and delete the throwaway files
(Phase 3).
